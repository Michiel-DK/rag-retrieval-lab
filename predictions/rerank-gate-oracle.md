# rerank-gate-oracle

Retrieval lane, written 2026-11-09 by the radar's Monday triage, before any run. Origin: radar verdict "2026-11-09 · Feed triage", item Per-Query Gating of LLM Rerankers for Multi-Hop Retrieval, https://arxiv.org/abs/2609.22880. Question: on NFCorpus, is the LLM rerank's gain over dense concentrated in queries that a feature available before the rerank call can pick out, so that skipping the reranker on the rest costs little?

## Prediction
Metric: per-query Δ nDCG@10 = `rerank_llm` − `dense`, from the committed `results/scores/rerank_llm.json` and `results/scores/dense.json` (the 323 queries in `results/query_order.json`; pooled Δ is +0.0885). Three numbers. (1) Oracle split: the share of queries with Δ > 0, Δ = 0 and Δ < 0, and the nDCG@10 the full rerank would gain if every Δ < 0 query were skipped (the oracle ceiling). (2) A one-feature gate from `results/rerank/dense_pool.json` (candidates: dense top-1 score; top-1 minus top-2 gap; count of pool scores above the pool median), feature and threshold chosen inside 5-fold cross-validation over queries (seed 42), reported as skip rate and held-out nDCG@10 of the gated system (rerank where the gate says call, dense otherwise) against the full rerank, with the lab's paired bootstrap. (3) The same two numbers for `rerank_zerank`. Baselines: `results/scores/dense.json` 0.3167, `results/scores/rerank_llm.json` 0.4052, `results/scores/rerank_zerank.json` 0.3881.
Direction and size: Δ > 0 on 40–55% of queries, Δ < 0 on 15–25%, exactly 0 on the rest (dense has recall@50 = 0 on a share of queries that no rerank of its 50-doc pool can change; counted from `results/scores/dense.json`: 63 of 323 queries, 19.5%). Oracle ceiling: about +0.02 nDCG@10 over the full rerank (0.01 to 0.04). The one-feature gate at a 30% skip rate costs **0.005–0.015** nDCG@10 against the full rerank and recovers under a quarter of the oracle ceiling; a CI that includes 0 is possible. Probability the gate is "barely discriminative" as in the paper (AUC < 0.65 for predicting Δ < 0): 0.7. For zerank the same picture with smaller magnitudes.
Kill clause: if no single-feature gate at ≥ 30% skips keeps the held-out nDCG@10 within 0.01 of the full rerank (CI upper bound on the loss), a pre-rerank gate is not a lever on NFCorpus and no learned gate is proposed. If the oracle ceiling is < +0.01, the post says the reranker is almost never harmful on this set and the question closes.

## Mechanism
The LLM judge reorders a 50-document pool. It can only help where relevant documents sit in the pool below rank 10, and it can only hurt where dense already had them in the top 10 and the judge demotes them; where recall@50 is 0 nothing changes. So the per-query Δ is bimodal with a point mass at zero, and the oracle ceiling is bounded by the harmed share times its mean damage. The paper's gate used 27 list statistics plus a query embedding and still had harm probabilities that were calibrated but barely discriminative, because such features describe the first-stage list, not whether the judge will disagree with it. A dense top-1 score says how confident dense is, and on biomedical NFCorpus queries dense confidence tracks "already right" only loosely, so the gate should separate safe skips (confident dense with high recall@10) from harmful ones poorly. 323 queries is small; the cross-validated number is the honest one and the per-fold spread goes in the post.
